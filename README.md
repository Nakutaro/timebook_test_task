# UI-автотесты: Авторизация и поиск сотрудников

Проект содержит автоматизированные UI-тесты на **Java + Selenide + TestNG** с формированием отчётов **Allure** для проверки формы авторизации и формы поиска/фильтрации сотрудников.

## Стек технологий
* **Java 17**
* **Selenide 7.5.1**
* **TestNG 7.10.2**
* **Allure Report 2.29.0** (`allure-testng`, `allure-selenide`)
* **AspectJ Weaver 1.9.22.1** (для детализации шагов `@Step`)
* **SLF4J Simple 2.0.16**
* **Maven** (`maven-surefire-plugin`, `maven-clean-plugin`, `allure-maven`)

## Структура проекта
```text
src/test/
 ├── resources/
 │    ├── index.html           # Тестируемая страница с формами авторизации и поиска
 │    ├── regression.xml       # Полный кроссбраузерный сьют (Chrome + Firefox)
 │    └── smoke.xml            # Быстрый Smoke-сьют (Chrome)
 └── java/
      ├── fixtures/
      │    └── WebFixture.java # Инициализация изолированного SelenideDriver, аттач HTML-кода и закрытие сессии
      ├── pages/
      │    ├── LoginPage.java  # Page Object формы авторизации
      │    └── SearchPage.java # Page Object формы поиска и таблицы результатов
      └── tests/
           ├── LoginTest.java  # Тесты входа, валидации и выхода из системы
           └── SearchTest.java # Тесты фильтрации, валидации дат/email и сброса фильтров
```

## Примеры покрытых сценариев

### Позитивные (успешные) сценарии
1. **Успешная авторизация (`LoginTest#login`, `LoginTest#loginByEnter`):**
    * Ввод валидных учётных данных (`test@test.test` / `test`) и отправка формы кнопкой «Вход» или клавишей `Enter` -> скрывается форма входа, открывается страница поиска сотрудников, в шапке отображается email авторизованного пользователя.
2. **Выход из системы (`LoginTest#logOut`):**
    * Нажатие кнопки «Выйти» -> возврат на экран авторизации, поля логина и пароля очищены.
3. **Отображение списка по умолчанию (`SearchTest#defaultEmployeeListShownAfterLogin`):**
    * После входа в таблице отображаются все 8 сотрудников, счётчик показывает `Найдено: 8`.
4. **Фильтрация сотрудников (`SearchTest#searchByExactEmail`, `searchByPartialName`, `searchByGender`, `searchByExactAge`, `searchByHireDateRange`, `searchByMultipleSkills`, `combinedSearch`):**
    * Поиск по точному Email, частичному совпадению ФИО без учёта регистра, полу, возрасту, диапазону дат приёма и набору навыков (логика «И»), а также комбинированный поиск по нескольким фильтрам одновременно -> счётчик `Найдено: N` и строки таблицы соответствуют ожидаемым записям.
5. **Сброс фильтров (`SearchTest#resetFiltersRestoresFullList`):**
    * Заполнение всех полей фильтрации и нажатие «Сбросить» -> поля возвращаются в исходное состояние, в таблице снова отображаются все 8 сотрудников.

### Негативные сценарии (проверка валидации и пустых результатов)
1. **Неверный формат Email при входе (`LoginTest#loginWithInvalidEmailFormat`):**
    * Параметризованный тест (`@DataProvider(name = "invalidEmails")`) с пустой строкой, отсутствием `@`, некорректным доменом или пробелами -> отображается алерт *«Проверьте Email / Неверный формат Email»*, поле подсвечивается рамкой ошибки.
2. **Неверный пароль или несуществующий Email (`LoginTest#loginWithWrongCredentials`):**
    * Параметризованный тест (`@DataProvider(name = "invalidCredentials")`) с валидным по формату, но неверным логином или паролем -> отображается алерт *«Ошибка входа / Неверный Email или пароль»*, форма поиска остаётся недоступной.
3. **Неверный формат Email в форме поиска (`SearchTest#searchWithInvalidEmailFormat`):**
    * Ввод неполного адреса (например, `ivanov` без домена) в фильтр поиска -> срабатывает валидация формата Email.
4. **Некорректный диапазон дат (`SearchTest#searchWithInvalidDateRange`):**
    * Указание даты «с» позже даты «по» -> отображается алерт *«Некорректный период / Дата «с» не может быть позже даты «по»»*.
5. **Отсутствие результатов поиска (`SearchTest#searchWithNoResults`):**
    * Поиск по несуществующему ФИО -> счётчик показывает `Найдено: 0`, в таблице выводится заглушка *«По заданным фильтрам ничего не найдено»*.

## Требования для запуска
* Установленный **JDK 17** или выше
* Установленный **Maven 3.8+**
* Установленные браузеры **Google Chrome** и **Mozilla Firefox** (для полного регрессионного прогона)

## Инструкция по запуску

### 1. Клонирование репозитория
```bash
git clone https://github.com/Nakutaro/timebook_test_task.git
cd timebook_test_task
```

### 2. Запуск тестов
* **Полный кроссбраузерный прогон (`regression.xml`, сьют по умолчанию):**
  ```bash
  mvn clean test
  ```
  *(или с явным указанием сьюта: `mvn clean test -Dsuite=regression`)*

* **Быстрый Smoke-прогон (`smoke.xml`, только Chrome):**
  ```bash
  mvn clean test -Dsuite=smoke
  ```

* **Запуск в headless-режиме (без графического интерфейса браузера):**
  ```bash
  mvn clean test -Dheadless=true
  ```

* **Ускоренный запуск в офлайн-режиме Maven (если зависимости уже загружены в локальный кэш):**
  ```bash
  mvn -o clean test -Dsuite=smoke
  ```

### 3. Формирование и просмотр отчёта Allure
После завершения тестов сгенерируйте и откройте интерактивный HTML-отчёт в браузере (включает вложенные шаги `@Step`, группировку по `@Epic`/`@Feature`, скриншоты при падениях и исходный HTML-код страницы `Page Source`):
```bash
mvn allure:serve
```
